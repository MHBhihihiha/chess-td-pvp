# 兵种朝向与动画规格（v9）

> 起因：玩家指出 ①人形兵种（步兵/重甲兵…）移动时腿和手应该有动作 ②所有兵种都会转向，转向中和转向后都要处理。
>
> **现状核实**：两件都没做。而且根源是同一个——**兵种贴图根本没接进渲染层**。
> 证据：`index.html` 里 `drawImage` 0 次、`new Image()` 0 次；兵种画的是
> `ctx.arc()` 一个圆 + `drawTeamMark()` 一个**永远朝上/朝下的小三角**（第 1167–1172 行）。
> 那个三角是固定的 `u.team === ME ? 1 : -1`，跟实际移动方向毫无关系。

---

## 1. 好消息：转向所需的数据已经现成

逻辑层已经在维护移动方向，**不用改 `logic.js` 一行**：

```js
u.stepDir = { r: target.r - u.row, c: target.c - u.col };   // 四向之一，且跨格后沿用
u.nextStep                                       // 目标格
u.moveProg                                       // 0~1，走到 nextStep 的进度
```

三点关键性质：

| 性质 | 意义 |
|---|---|
| `stepDir` 是**四向单位向量**（`{±1,0}` / `{0,±1}`），无斜向 | 朝向只有 4 种，不用做 8 向 |
| `stepDir` **跨格后仍沿用** | 兵停在建筑前打墙时，朝向不会丢 |
| `moveProg` 是**按速度均匀累加**的 0→1 | 可以直接当作**走路相位**，脚不会打滑（见 §3） |

---

## 2. 朝向模型：4 个方向 → 3 套姿态 + 水平翻转

| `stepDir` | 朝向 | 用哪套姿态 | 需要翻转 |
|---|---|---|---|
| `{r:+1, c:0}` | 向下（朝镜头） | `front` | — |
| `{r:-1, c:0}` | 向上（背对镜头） | `back` | — |
| `{r:0, c:+1}` | 向右 | `side` | 否 |
| `{r:0, c:-1}` | 向左 | `side` | **是（水平镜像）** |

**为什么是 3 套而不是 4 套**：左右本质是同一姿态的镜像，只有上下需要单独画。

**为什么本作必须先做 front / back**：
`DIR[team]` 决定蓝方 +1（向下）、红方 −1（向上），主线推进**全部是纵向**。
只做 `side` 一套姿态的话，兵会"横着走"走完整条路 —— 这是这个棋盘上最刺眼的错误。

---

## 3. 走路动画：相位必须绑速度，否则一定滑步

```js
// 用 moveProg 作为相位源（0~1 走一格）
var phase = (u.moveProg || 0) * WALK_STEPS_PER_CELL;   // 建议 2：一格两步
var frame = Math.floor(phase) % walkFrameCount;        // 两帧交替
```

配套三条：

1. **步频由 `speed` 隐式决定** —— `moveProg` 本身就是按 `def.speed * DT` 累加的，
   所以慢兵（重甲兵）自然迈得慢、快兵（气球兵）自然迈得快，不用单独配参数。
2. **停止时不重置相位**，只把相位**冻结**在当前帧 —— 半途停住不会"脚弹回并拢"。
3. **attack 状态打断 walk**，攻击结束回到 walk/idle 时相位继续，不从头播。

**两帧够不够？** 够。34px 下两帧交替 + 身体轻微上下浮动（`sin(phase*π) * 1.2px`）就足以读出"在走"。
四帧是给 100px 以上的单位用的，这里纯属浪费。

## 4. 状态机（含"转向中"和"转向后"）

```
        ┌──────────── 有 nextStep 且 moveProg > 0 ────────────┐
        ↓                                                     │
    [ walk ] ──到达/被挡──→ [ idle ] ──开火──→ [ attack ] ──冷却结束──→ [ idle ]
        ↑                       │                                   │
        └────── 继续移动 ────────┘                                   │
        └────────────────────────────────────────── 继续移动 ───────┘
```

### 转向的三个瞬间（玩家特别点出的部分）

| 时刻 | 处理 |
|---|---|
| **转向中**（`stepDir` 变了） | **不要瞬间翻面**。做一个短过渡：0.12s 内把旧姿态的**水平挤压**到 0 再展开新姿态（`scaleX: 1 → 0 → 1`），读起来是"转身"而不是"啪一下换了个人" |
| **转向后**（停下不动） | **保持最后一次的朝向**，绝不回退到默认方向。要有 `u.lastFacing` 缓存，且**跨状态保留**（走→停→打→停，朝向一直是最后那个） |
| **开火时** | 朝向 = **目标方位**（优先 `targetBuilding`，其次 `aimRow/aimCol`）。开火瞬间覆盖移动朝向，开完不立刻弹回，等下一次移动再更新 |
| **镜像时** | `side` 翻转必须**绕自身中心**翻（`translate(cx,cy); scale(-1,1); drawImage(-w/2,...)`），否则武器会甩到身体另一侧、位置整体偏移 |

### 一个必须避开的坑
`lerpPos()` 里已经处理过"转向那一 tick 位移是 √2 倍"的问题（做了减速）。
动画侧要注意：**转向的那一格不要立刻换姿态**，等 `moveProg > 0.15` 再切，
否则在拐角处会出现"一格之内闪两套姿态"的抖动。

## 5. 每个兵种需要几套素材

| 姿态 | idle | walk（2 帧） | attack |
|---|---|---|---|
| `front`（下） | ✅ 已有 `_idle` | ❌ 缺 | ✅ 已有 `_attack` |
| `back`（上） | ❌ 缺 | ❌ 缺 | ⚠️ 可复用 front（见下） |
| `side`（左右） | ❌ 缺 | ❌ 缺 | ⚠️ 可复用 front |

**attack 为什么可以少做**：攻击只发生在"贴着目标"时，而目标绝大多数在**正前方（纵向）**。
左右贴墙打建筑的情况很少，用 `side` 镜像 + 现有 front 攻击帧可以糊过去。
如果后面觉得别扭，再补 `side_attack` / `back_attack`（+32 张）。

### 命名约定（新）
```
unit_{key}_{team}_{pose}_{state}{frame}.png
  pose  : front | back | side
  state : idle | walk | atk
  frame : walk 才带，0/1

例：unit_infantry_blue_front_walk0.png
```
现有 `unit_{key}_{team}_{idle,attack}.png` 视为 `front_idle` / `front_atk`，**不用改名**。

## 6. 美术预算三档（要你拍板）

| 方案 | 内容 | 新增张数 | 优点 | 缺点 |
|---|---|---:|---|---|
| **A 全姿态** | front/back/side × idle/walk2/atk，attack 也分姿态 | **~160** | 最正统，任何角度都对 | 成本≈整个项目已有的量级 |
| **B 纵向优先（推荐）** | front + back 各 idle1+walk2；side 只做 walk2；attack 复用 front | **80** | 主线纵向完全正确，绕行时侧向也成立 | 侧向攻击是凑的 |
| **C 侧向单姿态** | 只做 side：idle1+walk2，靠镜像 | **48** | 最省 | **主线纵向会横着走**，最刺眼 |

**我推荐 B**：本作 90% 的位移是纵向推进，把预算压在 front/back 上最划算；
`side` 只做两帧走路（左右镜像），绕建筑时够用。

```

③ 兵种贴图接入（先用现有 32 张 idle/atk，验证尺寸与锚点）

⑥ 把「走路相位」「转向过渡」接上
```

**③④ 在任何新素材之前就能做**，而且是必须的：先让贴图在棋盘上站稳、朝向能转，
