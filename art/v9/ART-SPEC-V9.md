# 美术规格 v9 · 施工图

> 面向《棋盘塔防 · 蓝方 vs 红方》
> 目标质感：**皇室战争（Clash Royale）级别的厚涂卡通**
> 完整清单见同目录 `manifest.json` / `manifest.csv`（由 `dev/gen-art-manifest.js` 从代码数据自动生成）

---

## 0. 一句话验收标准

> **把三张图缩到 56px（棋盘格实际尺寸）并排放在一起，能一眼看出是"木 / 石 / 铁 / 装甲 / 金"五个不同阶段。**

做不到这一点，画得再细也是白费——玩家 90% 的时间看到的就是 56px。

## 1. 画法规则（逐条替换 v8 的病根）

| # | v8 的做法（丑的原因） | v9 必须这样做 |
|---|---|---|
| 1 | 全局一个描边色 `C_LINE`，1.9px 套在每个部件上 | **彩色描边**：取本体色的暗版（木→暗棕、铁→暗铁灰、金→暗金）。主轮廓 ≤1.2px，内部结构 0.6px 或干脆不描 |
| 2 | 受光面也描边 | **受光面不描边**，让亮部与背景自然相接 |
| 3 | 径向渐变（中心亮→边缘暗） | **单一左上 30° 主光**：顶亮 / 侧中 / 底暗三段色阶 + 暖色高光 |
| 4 | 部件各自成形后叠上去，接缝空着 | 每个部件底部压 **8~12px 软 AO**，交界处加接触阴影 |
| 5 | 木/石/铁/金共用一套公式只换色相 | 材质要能"摸出来"：木=颗粒+年轮+绳结 / 石=噪点+凿痕+苔 / 铁=斜向反射亮带+锈 / 装甲=切面硬边+铆钉阵列 / 金=高频亮暗条+宝石 |
| 6 | 正交俯视 | 等距 3/4 俯视（相机 30°），全图统一光轴 |
| 7 | 整个炮身染蓝/染红 | 主体材质中性，**阵营色只出现在旗帜、饰带、宝石**上 |
| 8 | 单张整图（炮口固定朝右上，无法旋转） | **分底座层 / 武器层**，武器层基准朝 0°（正右） |

## 2. 三层结构与锚点

```
art/v9/
├─ {family}_base_{era}.png      底座层：只画台座/墙体，顶部留 socket，无武器
├─ {family}_top_{era}.png       武器层：基础形态（Lv1~4 用）
├─ {family}_{branch}_top_{era}.png  武器层：分支形态（Lv5~10 用）
├─ {family}_body_{era}.png      整图（防御塔这种无武器建筑用）
├─ base_L{n}.png                大本营，6 张整图
├─ mine_L{n}.png                金矿，5 张整图
├─ unit_{key}_{team}_{frame}.png
├─ spell_{key}.png
├─ fx_{name}.png
└─ dc_{name}.png                装饰件（叠加用）
```

**画布**：512×512，透明背景（生成时出白底，再由 `dev/key_ai_asset.py` 抠图）

**锚点**：
- 底座层：**底部中心**对齐画布底部中心（占地中心）
- 武器层：**枢轴**（炮管转轴）放在**画布正中心**，炮口朝**正右 0°**
- 这三条必须严格遵守，否则拼合时会"炮管飘在台座外面"

## 3. 材质纪元 × 等级映射

10 级切成 5 个材质纪元，**每纪元一张母版**；纪元内的第二级靠装饰件叠加做差异。

| 纪元 | 材质 | 覆盖等级 | 造型关键词 |
|---|---|---|---|
| `e1` | 木 | Lv1–2 | 原木、绳索捆扎、粗糙小巧 |
| `e2` | 石 | Lv3–4 | 雕琢石块、崩边、微苔、稳重 |
| `e3` | 铁 | Lv5–6 | 铸铁板、铆钉接缝、工业感 |
| `e4` | 装甲 | Lv7–8 | 六角装甲、斜面裙板、加固节点 |
| `e5` | 金 | Lv9–10 | 鎏金饰板、雕花镶边、蓝宝石、传说感 |

---

## 4. 装饰件叠加规则（同纪元内的升级感）

同纪元有 2 级，**奇数级用母版，偶数级 = 母版 + 1 件装饰**：

| 目标等级 | 叠加装饰 | 效果 |
|---|---|---|
| Lv2 | `dc_rivets` | 加一圈铁铆钉，像被加固过 |
| Lv4 | `dc_moss` | 长苔藓，显旧但更厚实 |
| Lv6 | `dc_banner_blue` / `dc_banner_red` | 插上阵营旗，辨认度最高 |
| Lv8 | `dc_chain` | 挂铁链，重装感 |
| Lv10 | `dc_crown_tiny` + `dc_gem_blue` | 加王冠与宝石，终极形态 |

其余 6 件装饰（`dc_gold_band` / `dc_emblem_star` / `dc_cracks` / `dc_rust` / `dc_skull`）作为备用调剂，避免所有建筑"加同一个东西"。

> 这一步是"混合方案"的关键：AI 只负责把**材质质感**做对，等级递进由程序叠加完成，所以 10 级看起来一定是同一栋楼在长大，不会变成 10 栋无关的建筑。

## 7. 生产流水线

```
gen-art-manifest.js  →  manifest.json  →  ImageGen 逐张生成（用 item.prompt）
                                          ↓
                                    key_ai_asset.py 抠图 + 归一化
                                          ↓
                                    人工验收（56px 缩略对比）
                                          ↓
                                    接入渲染层（drawImage + 双层 + 旋转）
```

**提示词已经写好在清单里**，每条的 `prompt` 字段是完整可用的英文提示词，包含：对象描述 + 材质纪元 + 分支造型要求 + 统一风格尾巴。

### 7.1 实测生产参数（批次①跑完后确定，后续批次直接照用）

**共享构图网格**（关键：两层不能用同一个"填满画幅"规则，否则炮管会和底座一样大）

| 层 | 命令参数 | 含义 |
|---|---|---|
| 底座 base | `--anchor bottom --fit 0.86` | 物体最长边占画幅 86%，底边对齐（地面线统一） |
| 武器 top | `--anchor pivot --fit 0.60 --pivot-x 0.30 --pivot-at 0.5,0.455` | 长度占画幅 60%，枢轴放在宽度 30% 处，并落在画幅 (0.5, 0.455) 的 socket 位置 |
| 整图 body | `--anchor bottom --fit 0.94` | 大本营 / 金矿 |

**抠图必带参数**：`fill_enclosed_bg` 默认开启。生图会把「被结构围住的白色区域」（如木架内部的三角空腔）留成白块，外部 flood fill 够不到，必须靠连通域分析按面积阈值一并删掉。

**旋转**：直接用 2D 旋转（`ctx.rotate`），**不要**做等距椭圆压缩。参照 Bloons TD 的做法：3/4 视角的厚涂素材在平面内旋转，观感自然且实现简单；加椭圆压缩反而会让炮管变形。

### 7.2 验收清单（每条资产过一遍）

- [ ] 56px 缩略后仍能分辨材质纪元
- [ ] 底座与武器拼合后，武器坐在 socket 上、不悬空
- [ ] 武器层炮口朝正右，旋转四个角度无穿帮
- [ ] 边缘无浅色光晕（深底上检查）
- [ ] 无地面 / 无底板 / 无独立投影
- [ ] 阵营色**没有**烘进贴图（旗帜布面留空，走 `dc_banner_*` 叠加）

## 8. 已知风险与对策

| 风险 | 对策 |
|---|---|
| 生图模型不保证真透明（会把透明画成棋盘格） | 已实测：`background:"transparent"` 无效，必须走 `key_ai_asset.py` 抠图。**每条都在流水线里强制过一遍** |
| 10 级之间画风漂移 | 每家族第一张定为"风格锚点"，后续用 `image1` + `image2` 双参考喂给它 |
| 武器层枢轴对不准 | 生成后统一按"炮管中心线"重新对齐，枢轴强制放画布中心（脚本可做） |
| 分支造型 AI 理解偏差（比如双管画成一根粗管） | 提示词里已经写死 `TWO parallel cannon barrels side by side (left and right muzzles)`；验收时逐条比对 |
| 56px 下细节糊成一团 | 见 §0；必要时对每个资产再出一版"简化版"（减内部细节、加强明暗对比） |

## 9. 渲染层需要配合的改动（贴图接入时）

1. `drawImage` 双层绘制：`base` 静态 + `top` 按规则绘制
2. **顶部构件分三类（重要）**：
   - **旋转类**（炮塔 / 箭塔 / 迫击炮塔）：`top` 绕枢轴转到瞄准角
   - **定子类**（特斯拉电塔 / 脉冲塔 / 大电塔 / 法师塔 / 白魔法塔 / 黑魔法塔）：
     `top` **固定在底座正中、完全不转**。方向性只体现在打出去的东西上——
     电弧和法球靠弹道的 `from → to`，电磁波是同心圆（本就无方向）
   - **无攻击类**（防御塔 / 水晶塔 / 碉堡塔）：完全没有攻击，`top` 构件
     **静态居中绘制**即可，不读瞄准角、不做插值
3. 等级 → 文件名映射（`level` → `era` + 装饰件组合）
4. 阵营 → 装饰件选择（`dc_banner_blue/red`）
5. 旧矢量绘制保留为 fallback（文件缺失时不能让游戏崩）

## 10. 装饰件（v9 新增）

**目的**：解决"同一材质纪元内两级长得一模一样"的问题。
10 级 = **5 张纪元母版 + 纪元内第 2 级挂 1~3 件装饰件**。装饰件只做加法，永不改母版。

完整规则见 **`deco-plan.json`**（程序可直接读，不要手抄到代码里）。

| 等级 | 纪元 | 装饰 |
|---|---|---|
| 1 | 木 | — |
| 2 | 木 | 铆钉条 + 星徽 |
| 3 | 石 | — |
| 4 | 石 | 苔藓 |
| 5 | 铁 | 铆钉条 |
| 6 | 铁 | **阵营旗**（第一次出现阵营色） |
| 7 | 装甲 | 锈迹 |
| 8 | 装甲 | 铁链 + 锈迹 |
| 9 | 金 | 金饰带 |
| 10 | 金 | 金饰带 + 小王冠 + 蓝宝石 |

### 两类装饰件，用两种方式生产

| 类型 | 文件 | 生产方式 | 理由 |
|---|---|---|---|
| **造型件**（8 件 + 红旗） | 铆钉/金饰带/星徽/宝石/王冠/兽骨/铁链/阵营旗 | ImageGen 生成 + 抠图 | 有明确造型，需要手绘质感 |
| **脏化层**（3 件） | `dc_cracks` / `dc_moss` / `dc_rust` | **程序化**（`dev/gen_deco_tex.py`） | 要贴在表面上，必须是软边可平铺的 alpha 纹理；生成模型给的是硬边色块，贴上去像补丁 |

脏化层参数（已调过两轮）：
- `dc_cracks` 覆盖率 ~16%，11 条主纹 + 分叉，末端锥形收细
- `dc_moss` ~47%，成片斑块 + 高频绒毛，模糊半径仅 0.4（第一版 1.2 像水渍）
- `dc_rust` ~37%，大块锈斑 + 细颗粒

### 三条硬规则
1. **装饰件画在 base 之上、top 之下** —— 否则会盖住炮管/法球，旋转时露出破绽
2. **阵营色只允许由 `dc_banner_{team}` / `dc_skull`（红方）提供**，绝不烘进母版
3. **`dc_cracks` 是状态叠加**，不是等级装饰：`hp/hpMax < 0.5` 时出现，alpha 随血量下降线性提高

### 阵营差异
蓝方 Lv2+ 挂**星徽**，红方 Lv2+ 改挂**兽骨战利品**（同位置互斥）。
其余装饰件两队通用 —— 这也是为什么它们必须是中性材质（铁/金/石头）。
