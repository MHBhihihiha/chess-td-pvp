## 升级总规则
- 等级 1-4：每级 **攻击/生命 +10%**
- 等级 4→5：**二选一分支**
- 等级 5-9：每级 **攻击/生命 +30%**
- 等级 9→10：**攻击/生命 +60%**（终极形态）
- 升级费用：`基础造价 × (1 + 0.35×等级) × 1.22^等级`，即**逐级递增**且**越贵的建筑升级越贵**
- **升级不回血**：只把「升级前后最大血量的差值」加到当前血量上
  （`400/500` 升到 `600` → 变成 `500/600`）
- 金矿单独一条曲线：1-4 级每级 +30%，**4→5 级 +60%（终极金矿）**，最高 5 级

# 本轮修掉的关键 bug（都是寻路/规则层面的真问题）

1. **`wallAt()` 返回值当布尔用** —— 它返回的是建筑对象，写成
   `wallAt(ar,ac) ? 0 : dists[ar][ac]` 永远取 0，导致「只打兵」的兵的路线图
   也会指向墙、甚至走进墙格。这是本轮最隐蔽的一个 bug（`building-spec-test` 的
   「每个可达格都指向距离更小的邻居」不变量抓出来的）。
2. **打兵型 / 拆建筑型必须是两张不同的路线图** —— 之前只有一张，
   所以「墙算不算目标」没法按兵种区分。现在 `state.field`（打兵）与
   `state.fieldSiege`（拆建筑）分开算，`fieldFor(state,u)` 取对应的那张。
   步兵被墙挡住时会在通道行让位去别的空列，攻城兵则走到墙前开始拆。
3. **打击位只有紧贴大本营的列才算** —— 之前整行都当 0 距离，导致处在
   非大本营列的兵以为「到了」就停下，实际还差两格够不着，永远打不到大本营。
4. **射程判定要用格距离（切比雪夫）** —— 之前用欧氏距离，斜对角的敌人
   被算成 1.41 格而打不到。这是「胜负条件根本打不出来」的直接原因：
   修好前 300 秒内双方大本营一滴血不掉，只能靠决胜时刻烧掉。
5. **打击位那一行允许横移** —— 否则在非大本营列推进到底的兵永远够不着大本营。
6. **`justDamaged = 0` 被 `||` 当成「没挨过打」** —— 大本营自愈的等待期失效，
   改成 `!= null` 判断。
7. **冷却浮点残渣** —— `5 - 0.05×100` 会留下 `9.4e-15`，导致「冷却明明走完
   却派不出去」，统一收尾归零并留 0.001 容差。
8. **防御塔光环没在建造/摧毁时重算** —— 只有升级时算了，所以新盖在金矿旁边的
   建筑拿不到减伤。现在 `placeBuilding` / `removeBuilding` 都会 `reloadNeighbors`。
9. **金矿能升到 10 级** —— 加了 `def.maxLevel` 支持，金矿封顶 5 级。
10. **升级不再回血**（按你的要求改掉了原来的「按比例保留」）。

## 当前玩法（已实现）
- 10×10 棋盘；行1-5 红方（敌）、行6-10 蓝方（你）；行A/行B 是棋盘外的出兵通道
- 双方 2×2 大本营在 (行1-2,列5-6) / (行9-10,列5-6)；被摧毁即输
- **大本营外侧那一行是「打击线」**：蓝方在行8、红方在行3；兵走到那里就停下开打
- 地面兵棋盘内只沿本列推进；被敌方建筑挡住 → 停在墙前拆墙（「堵」）
- 横向移动只在通道行发生：正上方被堵 → 沿通道行找别的空列（你设计的那条妙计）
- 空中兵无视建筑直飞；兵种分「优先打兵/大本营」与「优先拆建筑」两类
- **点建筑可查看详情并升级**：显示血量/攻击力/射程/收入/训练间隔，升级后数值提升（最高 5 级）
- 建筑与士兵都有血条，挨打闪白
- **决胜时刻**：5 分钟后双方大本营一起持续掉血（越来越快），保证分出胜负

## 设计上的一个关键事实（供你摆阵参考）
- 蓝方打击线 = **行8**，红方打击线 = **行3**
- 所以「墙」要砌在行8（或行3）才有防御意义；砌在行10 是没用的（在打击线**后面**）
- 整行墙能完全挡住地面兵，但墙有血量、会被拆掉

## 电磁波怎么实现（`spawnWave` / `updateWaves`）
- 波从塔心向外的圆环，半径按 `WAVE_SPEED = 6 格/秒` 增长，上限 = `range + 0.55`
- **关键**：用 `prevR / radius` 卡出一层薄环，只有落在 `(prevR, radius]` 里的单位才吃伤害
  - 波前扫过的敌人不会补伤（站位能躲）
  - 波过去之后才走进来的敌人也不会补伤
- 倒序遍历 `state.units`（`damageUnit` 会 splice，正序会漏检）

## 电的质感（渲染层）
- `drawVoltBolt()`：三层描边（外发光 0.22 / 中束 0.78 / 白芯）+ 末端电光；
  随机种子混入 `(弹道id, 时间)`，每 25ms 重扭一次；两端振幅收敛、中间最抖
- `drawWaves()`：扩散圆环 + 圆周 30 段锯齿电弧，越往外越淡；
  画在**地面之上、建筑之下**（贴地冲击波）
- 链式闪电不需要额外渲染：第 2、3 道的 `from` 就是上一个敌人的位置

## 本轮抓到的两个管线问题

### 1) 并行生成会互相覆盖（严重）
同时发多个 ImageGen 调用时：
- `output_dir` **不生效**，全部写进同一次调用指定的目录
- 文件名按「提示词前 30 字 + 秒级时间戳」生成，同一秒完成的两张会**撞名互相覆盖**

实测：一次发 4 个请求，只落盘 2 个文件。
**结论：ImageGen 必须严格串行，一次一张。** 后续批次不要再并行。

### 2) 枢轴参数是「按武器形态」而不是全族通用
- 炮管类：`--fit 0.60 --pivot-x 0.30 --pivot-at 0.5,0.455`（绕炮尾转轴）
- 弓弩类：`--fit 0.74 --pivot-x 0.50 --pivot-at 0.5,0.40`（绕弓身中心握把）
用炮管参数套弓类会导致弓缩在底座框里、看着像"箱子里插了根棍"。

1. 第 1 版歪 20°（旋转会晃）→ 报废
2. 第 2 版垂直了，但自动加了**木架台座**（和底座层重复）→ 报废
3. 第 3 版过度装饰成一堆乱木头 → 报废
4. 第 4 版改成极简描述（"就一个球 + 短颈 + 法兰盘，别的什么都不要"）→ 成功

**教训**：竖直类武器层要写"极简 + 底层是法兰盘 + 什么都没有 + 少而大的形状"，
否则模型会自己补一堆结构，既遮挡又没法用。

## 第五套参数：竖直柱体
`--anchor pivot --fit 0.50 --pivot-x 0.50 --pivot-y 1.0 --pivot-at 0.5,0.50`
枢轴贴到包围盒**底边**（pivot-y=1.0），落点放画幅 0.50。
物理上限：`h ≤ 0.50 × 512 = 256px`——台面以上的空间就这么高，没有余量。
**这是竖直类武器的硬上限，再想要大就只能改画幅或缩底座。**

# 2026-10-27 · 电 vs 波：把两种视觉语言拆干净

# 待办 / 已知问题（2026-10-27 记录，暂不修）

## B-01 电击弹道不「贴着」移动中的敌人
**现象**：特斯拉电塔 / 大电塔 攻击移动中的敌人时，一次攻击内闪电只指到**开火那一帧**敌人的位置，
不会随着敌人继续移动而实时改变方向和长度。

**根因定位**：`logic.js` 里弹道对象同时有 `to`（终点）和 `targetId`。
淡出循环里**只有 `targetId` 能查到活着的单位时才更新 `p.to`**：
```js
if (p.targetId) { var tt = state.units.filter(o => o.id === p.targetId)[0];
                  if (tt) { p.to = centerOf(tt); ... } }
```
这段本身是对的，问题在渲染层：`drawVoltBolt(x0,y0,x1,y1,...)` 用的是
`cellRect(p.from)` 和 `cellRect(p.to)` 算出的像素坐标，但 `p.to` 是**格坐标**，
敌人格内移动（`moveProg` 插值）时坐标只在跨格时才跳变 → 闪电看着是"打到格心"而不是"贴着人"。

**修法（等贴图全做完再做）**：
1. 渲染层改成按 `unit.row/col + moveProg` 算**亚格精度**的连续坐标
2. 或者给弹道加 `followTarget: true`，由渲染层每帧直接从 `targetId` 取敌人的实时像素位置
3. 同时把 `drawVoltBolt` 的起点也跟随塔顶（目前是开火时的炮口位置，静止塔无所谓）

**优先级**：P2（手感优化，不影响判定）

# 2026-10-27 · 兵种朝向与走路动画：现状核实 + 规格

## 玩家提问
① 步兵/重甲兵等人类兵种移动时腿和手有没有动画？
② 所有兵种都会转向，转向中和转向后要考虑到。

## 核实结果：两件都没做
- `index.html` 里 `drawImage` **0 次**、`new Image()` **0 次** → 兵种贴图从未接入渲染层
- 兵种画的是一行 `ctx.arc()` 圆 + `drawTeamMark()` 里一个**固定三角**
  （`u.team === ME ? 1 : -1`），永远朝上/朝下，跟实际移动方向无关
- 所以不存在"走路动画"和"转向"——连静态贴图都还没上

## 好消息：转向不需要改逻辑层
`logic.js` 已经维护好了三样东西：
- `u.stepDir = {r, c}` —— 四向单位向量，且**跨格沿用**（兵停在墙前打墙时朝向不丢）
- `u.nextStep` —— 目标格
- `u.moveProg` —— 0~1，按 `def.speed * DT` 均匀累加

⇒ 朝向只有 4 种（无斜向）→ **3 套姿态 + 水平翻转**即可覆盖
⇒ `moveProg` 可直接当走路相位 → **步频天然与速度绑定，不会滑步**

## 关键设计决定（写进 `art/v9/UNIT-ANIM-SPEC.md`）
1. **必须做 front + back**，不能只做 side：`DIR[team]` 决定蓝 +1 向下、红 −1 向上，
   主线推进全是纵向。只做 side 会让兵"横着走"走完整条路 —— 最刺眼的错误。
2. 走路两帧足够（34px 下两帧 + 身体上下浮动 1.2px 就能读出"在走"），四帧是浪费。
3. 停止时**冻结相位**，不重置，避免"脚弹回并拢"。
4. **转向中**做 0.12s 的水平挤压过渡（scaleX 1→0→1），不要瞬间翻面。
5. **转向后保持最后朝向**（`lastFacing` 缓存，跨状态保留），绝不回退默认方向。

## 三条设计决定

### 1) 兜底优先，缺图不崩
`img()` 任何一张没加载好就返回 `null`，调用方**自动退回原来的矢量画法**。
所以贴图缺失时游戏照跑，只是那一件用旧样式 —— 而不是白屏。

### 2) 只有「炮管朝右」的家族才旋转
`SPIN_KEYS = { cannon, arrow, mortar }`。
法师球 / 特斯拉线圈 / 防御塔水晶都是**无方向**的，传 `null` 一律 0° 摆正。
（这是之前三轮玩家反馈收敛出来的三分法，现在落到代码里了。）

### 3) 脏化层必须按 base 剪影做 mask
苔藓/锈迹/裂纹如果不 mask，贴上去就是**一块方形补丁**，比不贴更假。
做法：离屏 canvas 先画纹理，再 `destination-in` 叠 base → 得到贴合轮廓的贴图。
结果按 `(纹理, 底座)` 缓存，同屏几十栋楼也只算一次。苔藓/锈迹只取下半部（底部才长）。

## 朝向状态机
- 方向来源：`u.stepDir`（四向、跨格沿用）→ `down/up/left/right`
- **转向后保持**：`lastFacing[id]` 缓存，停下/开火都不清除
- **拐角保护**：`moveProg > 0.15` 才换姿态，否则一格之内会闪两套姿态
- 目前只有 front 一套姿态，`left` 用水平镜像给反馈；`back/side` 素材到位后**只改 POSE 表**
- 走路：暂无帧，用 `sin(moveProg * 2π)` 做 0.045 格的上下浮动 —— 相位直接绑 `moveProg`，
  天然跟速度同步、不会滑步

## 三个关键决定

### 1) 必须用 `lighter` 叠加混合
特效图是「纯黑底 + 亮度键控」出来的，alpha 是连续的。
用普通 `source-over` 画，半透明的暗部会把棋盘**压灰**（一层脏雾）；
用 `lighter`，暗部等于加 0，只有亮的部分发亮 —— 这才是火光该有的样子。

### 2) 出生/死亡不碰逻辑层
逻辑层没有 birth/death 事件，但渲染层本来每帧就能看到"谁新出现了、谁不见了"，
所以用一张 `seenUnits` 表做差分。
好处：`logic.js` 一行没改，以后逻辑层重构也不受影响。
死亡位置取**上一帧的位置**（兵已经从数组里消失了，当场取不到坐标）。

### 3) 尺寸换算踩了一脚
爆炸初版 `aoePx * 2.55` → 实际 2.7 格宽，几乎压满小棋盘。
改成 `1.95` ≈ 2 格，刚好覆盖迫击炮的伤害范围。**特效尺寸要跟逻辑半径对齐，不能凭手感。**

## 兜底
每个绘制点都是 `if (!ART.drawFx(...)) { 原来的矢量画法 }`。
贴图没加载完时退化为旧效果，不会出现"没特效"或白屏。

### 1) 提示词里"要求看到阵营色"会把镜头拽回正面 ⚠️

3. **普通档被 upgradeBudget 0.20 锁死**：大本营永远 Lv1、收入 5/秒，物理上不可能收尾。
4. `!allIn` 守卫 45s 全冻结发育，推家一波被吃掉就白亏。
