# A. 四张升级图标重制

## A1. 风格锚定（照这段话写提示词就能做出同风格）

放置栏图标（`cannon_base/top_e*`、`unit_*_idle`、`spell_*`、`base_L*`）共同属于一个风格家族。五个关键词锁死它：

| # | 关键词 | 具体口径（可判定） |
|---|---|---|
| 1 | **手绘贴图的低模渲染**（hand-painted 3D） | 形体是**大块硬切面**堆出来的（不是平滑曲面），切面上再铺手绘笔触：木有年轮与纤维、铁有斜向镜面亮带、石有凿痕与麻点。禁止纯色平涂。 |
| 2 | **单一左上主光 30°–40°，右下冷补光** | 全图只有一个亮部方向（左上方），且**受光面更暖、背光面更冷**（蓝紫灰）。这是厚涂卡通"活"的关键。禁止中心亮→边缘暗的径向渐变。 |
| 3 | **无通用描边** | 全家族都**没有**一圈统一的深色 outline。形体靠"暗部自己够暗"与背景分开。允许的只有 ≤1px 的本体色暗边（form-edge），不是灰色。 |
| 4 | **材质可辨认** | 缩小到 46px 仍要靠**表面纹理的疏密与反射特征**判断材质：草绳=缠绕颗粒带、铁=一条斜亮带、木=平行纹、石=凹凸麻点。禁止"同一套公式只换色相"。 |
| 5 | **高饱和小面积 + 低饱和大面积** | 主体约 **75–80% 面积是低饱和天然色**（棕/灰/石/钢），语义色只占 **20–25%**，集中在"能量核心"处。明暗三档：亮部 / 中间调 / 深暗部；深暗部**保留色相、不发黑**（最暗不越过 `#221a16` 档）。 |

**正面参照**：`cannon_top_e1.png`、`unit_infantry_blue_idle.png`、`base_L1.png`、`spell_*`
**反面参照**（v1 之前的旧版 4 张，已废弃）：扁平矢量 + 6px 灰描边 + 单色渐变 + 烘死的灰椭圆投影

## A2. 四张图标的画面定义

设计轴：**物体族**决定造型语言（建筑 = 塔/墙，士兵 = 装备），**语义色 + 动势**决定攻击/生命。
四张的**剪影必须互不相同**（46px 下靠剪影就能分）——这是第一原则，**实测已确认 uAtk 违反**（见 A6）。

| | 剪影形状 | 动势 | 语义色 |
|---|---|---|---|
| bAtk 建筑攻击 | 横向重块 + 右上伸出 | 动态、有喷发 | `#ff8a5c` 暖橙 |
| bHp 建筑生命 | 横向宽方块（矮胖） | 静止、沉 | `#7ec8ff` 冰蓝 |
| uAtk 士兵攻击 | **宽直斜带**（非细月牙） | 动态、有轨迹 | `#ffd479` 金 |
| uHp 士兵生命 | 圆形（顶宽底窄） | 静止、稳 | `#7ef0a0` 翠绿 |

### ① bAtk · 建筑攻击 ——「铁炮位开火」 ✅ 已产出，验收通过

- **主体**：v9 **铁纪元（e3）** 炮管，架在用凿痕石块砌出的矮炮位上（能看出是"建筑的一部分"）。炮口朝**右上 25°**。
- **配色**：铁 `#6E655C`（亮）/ `#3E3833`（暗）/ 锈斑 `#8A5A34`；石 `#A89A86` / `#5D5347`；炮口火光 `#FF8A5C` → `#FFD0A8` → `#B03A18`；炮管根部余热 `#C2522E`。
- **必须避免**：阵营色塔身、俯视平面炮、**向上箭头**（旧版符号化病根）、灰描边、地面投影。
- **实测**：现资产读作"石基座上的铁炮 + 硬边橙焰"，无投影无边框，通过。

### ② bHp · 建筑生命 ——「石墙 + 铁箍 + 护盾晶核」 ✅ 已产出，验收通过

- **主体**：厚石砌城墙（横向 4:3），正面横跨两道锈铁箍，中央嵌**冰蓝护盾晶体**（菱形，内发光），冷光沿石面铺开。
- **配色**：石 `#B3A692` / `#7A6E5E` / `#4C4338`；苔 `#5A7A4A`；铁 `#6B5F52`；冰蓝 `#7EC8FF` / `#D8F2FF` / `#2E6FA8`。
- **必须避免**：画成盾牌（撞 uHp 剪影且读不出"建筑"）、整块染蓝（蓝只占 ~20%）、城墙缺口。
- **实测**：46px 下读作"石块墙 + 蓝晶"，略偏"方块"但可接受。

# B. 棋盘草地质感升级

## B1. 诊断：为什么"双色块 + 单层噪点"显得平

把旧色值换算成 HSL **和** Lab（两把尺子都要看，这是 v1 的教训）：

| | hex | HSL H | HSL S | HSL L | Lab L\* |
|---|---|---|---|---|---|
| `GRASS_A` | `#5da04a` | 106.7° | 36.8% | 45.9% | 59.9 |
| `GRASS_B` | `#4d8b3c` | 107.1° | 39.7% | 39.0% | 52.3 |

**结论：色相差 0.4°、Lab ΔL\* 只有 7.6。** 不是"两种绿"，是"同一种绿的两种晒印深浅"。

四条病因：

1. **只有两个明度台阶，且都在中间调**。真实草地在俯视下受光簇尖到 L\* 70+、簇间阴影到 L\* 25，跨度接近 45；旧版只有 7.6。
2. **零色温差**（H 都是 107°）。真实草地：受光草尖偏黄（85–95°），背光深处偏青（120–135°）。**温度差是"活"的最大来源。**
3. **只有单一频率**：100×100 贴片、520 笔 1–3px 短线，周期在 300–560px 棋盘上重复 3–5.6 次，**且两格共用同一个 pattern** → 均匀麻点。缺中频（簇）与大频（光楔）。
4. **格线太弱，靠"干净"才读得出**。`rgba(16,34,18,.30)` ΔL\*≈17 已经很勉强；草地一旦有质感就会被淹没。

## B2. 目标色板（v2 修订）

### 双色格

| | hex | HSL H | HSL S | HSL L | **Lab L\*** |
|---|---|---|---|---|---|
| `GRASS_W` 暖格 | **`#60A246`** | 103.0° | 39.7% | 45.5% | **60.6** |
| `GRASS_C` 冷格 | **`#4C8850`** | 124.0° | 28.3% | 41.6% | **51.5** |
| 差值 | — | **ΔH 21.0°** | ΔS 11.4pp | ΔL 3.9pp | **ΔL\* 9.1** |

**三条设计约束（全部实测满足）**：

1. **棋盘台阶 = 旧版的强度**。旧版 Lab ΔL\* 7.6，新版 9.1 —— 略强，但不再是我 v1 犯的 14.9（= 旧版两倍，那会把棋盘读成铺装砖）。
2. **整盘平均明度与旧版完全一致**：56.05 vs 56.05。玩家的"整体色调记忆"不被改掉（B8-3 因此必然通过）。
3. **"活"由色温承担**：ΔH(HSL) 从旧版 0.4° → **21.0°**。

> ⚠️ **HSL 明度不可当感知明度用**：新色板 HSL ΔL 只有 3.9pp，看着比旧版"更平"，但 Lab ΔL\* 是 9.1，**实际更强**。因为冷格饱和度低（28.3% vs 39.7%），HSL 的 ½(max+min) 公式在高饱和色上系统性高估明度。**凡是"明度差"一律用 Lab L\* 验收。**

### 每格抖动（杀掉"印刷棋盘感"）

不做实时 HSL 运算。**预生成 6 个变体，按 `(row,col)` 哈希取**（幅度 L\* ±1.5 / S ±3pp / H ±2°）：

```js
var W_VAR = ['#5FA040','#64A947','#5F9947','#63A64A','#5B9D44','#5DA246'];
var C_VAR = ['#468648','#4D8F50','#4C804F','#508B55','#49834E','#4C8852'];
```

> **v2.2 换过这组数组**：v2 的 6 个 hex 是我手挑的，**H 抖动不对称**，导致实测相邻格 ΔH 均值只有 17.5°，比色板理论值 21.0° 低了 3.5°（等于把暖冷分离白白削掉 1/6）。这一组是按 **HSL 对称抖动**（H ±2°、S ±3pp、L ±1.5pp）算出来的，均值为 103.1° / 124.1° → **ΔH 20.97°**，与色板理论值一致。
> 规律：**抖动变体必须对称生成，不能手挑**——手挑的均值一定漂。

### L2 的两条硬规则（v1 的全部错误都在这）

1. **必须有平台段**：`addColorStop(0, hex)` → `addColorStop(0.45, hex)` → `addColorStop(1, 同色 α0)`。
   纯径向衰减的平均贡献只有峰值 α 的 **1/3**，α=0.10 时只有 ~3% 混色 = 看不见。
   末端**必须收"同色全透明"**（`rgba(44,82,34,0)`），**不能收 `rgba(0,0,0,0)`** —— 后者会朝透明黑插值，边缘发灰。
2. **圆斑=石头，拉长+旋转=草丛**。`ry/rx` 必须在 0.35–0.60，且逐斑旋转 20°–70°。
   v1 的 `rx 0.16–0.34s` + `ry/rx 0.55–0.80`（近圆、且大到覆盖半格）在 44px 格里就是"4–6 颗卵石"。**这是"读成铺装砖"的第一贡献者。**
3. **α 上限与半径成反比（重要）**：α 从 0.16 提到 0.30 只有在 `rx ≤ 0.20s` 时才安全。
   半径大 + α 高 = 又大又深的块 = 回到石头。**改 α 时必须同时检查 rx**，否则会把第 2 条修好的效果又推回去。
   > 实测依据：实现方把 α 提到 0.32、B8-1 从 20.8 升到 30.1（达标），我复核时确认那次改动**同时**缩小了半径，两个变量一起动才成立。

### L5 的方向：**散开**（我原来的"不要散开"裁决撤回，见勘误 16）

实现方提过"草尖散开版"（`dev/_gen/board_bladespread_candidate.png`），我最初裁决"不采用、保持同一象限"。**这个裁决是错的，撤回。**

- **我错的因果模型**：我以为 L5 是"唯一体现光照方向的层"，散开会让光变成环境光。**但俯视草地里的草叶朝向本来就是随机的** —— 光照方向由 L1 光楔、L2 斑块的明暗分布、以及图标本身的左上光共同承担，**不由叶片朝向承担**。散开不损失任何光照信息。
- **实测反证**：同向短划（`-90°±40°` 收在一个象限）在 4× 超采样柔化后是一串同向亮条，**读作"斜雨"**。而且关掉 L5 后贴图自带的同向斜痕更明显 —— 说明"同向"本身就是病根。
- **定稿（与实现一致）**：方向 `-90° ± 70°`（近似全向、略偏上），既去掉斜雨，又保留一点"草略朝上"的倾向。
- **但长度要收**：实现当前长度三档最高到 `0.24s`（cell 44 → **10.5px**），已撞到 C3 的 11px 天花板。**上限压到 `0.18s`（8px）**，α 上限压到 **0.18**。理由与 B5 完全同构：**超过 11px 的亮条，无论方向如何都读作刻痕。**
- 若 B8-5（单格 std 上限 9）在 k=0.75 下被顶破，**第一个就砍 L5 密度 20→14**（而不是砍 L2）。

### L8 雕刻槽

```js
g.strokeStyle = 'rgba(10,24,12,.52)';      // 暗槽，画在格线本身（v2.2 定稿值）
// 亮棱：同一位置右/下偏 1px
g.strokeStyle = 'rgba(216,244,186,.30)';
```
- 半场中线（`y = by + 6s`）：`rgba(12,26,14,.74)` 3px + 下方 1px `rgba(255,244,214,.34)`
- 通道药片标签底 alpha **+0.06**

**这三组值的来历（别凭感觉调）**：格线/中线都是"草地变强的因变量"——
| 阶段 | 格线 暗/亮 | 中线 暗 | 实测中线 ΔL\* |
|---|---|---|---|
| v1（纯色+麻点） | `.30 / —` | `.42` | — |
| v2（首版贴图 α.34） | `.40 / .22` | `.50 → .60` | 17.3 → 18.7 |
| **v2.2（细叶贴图 α.36 + 新色板）** | **`.52 / .30`** | **`.74`** | `.60`→**17.0**、`.68`→17.9、**`.74`→19.2** |

规律：**每加强一次草地质感，格线与中线都要再加深约 25–30%**，否则必然掉 B8-2。下一个人若再改贴图 α 或换贴图内容，**先把 B8-2 跑一遍再决定要不要动这三个值**。
宽度仍是 3px —— 中线再宽会读成"一条路"，那就不是分界线了。

## B4. 草叶画法

| 画法 | 观感 | 结论 |
|---|---|---|
| 短直线（旧版） | 胡茬 / 毛刺 / 麻点 | **否决**（"麻点感"的直接来源） |
| 簇状三角 | 针叶 / 锯齿 | 仅 `s < 26` 时廉价替身 |
| **二次贝塞尔叶片** | 有弯曲、尖端收细、有厚度 | **采用** |

```js
g.beginPath();
g.moveTo(x, y);
g.quadraticCurveTo(x + len * 0.42, y - len * 0.62, x + len * 0.78, y - len);
g.lineWidth = Math.max(0.8, s * 0.030);
g.lineCap = 'round';
g.stroke();
```
**注意**：上式的叶尖方向是**基准**，实际每根必须叠加 A/B3-L5 的 `ax/ay` 抖动，否则读成斜线网纹。

每格总量：暗簇 6 + 亮簇 3 + 草尖 20 + 微点 24 ≈ **53 次绘制 / 格 × 120 格 ≈ 6.4k**（`s≥32` 档；`s<20` 时 tips 与 light 归零）。

## B5. 贴图：改用程序化细叶（v1 路线已证伪）

### 为什么放弃 ImageGen 草叶贴图

| 证据 | 数值 |
|---|---|
| 出图内容是**宽叶蕨状团簇**，每团约 1 格大 | 44px 格里只有 ~6–10 个团块 → 读作**鹅卵石** |
| 四象限镜像拼接造成**精确四重对称** | 与自身水平镜像 / 垂直镜像 / 180° 旋转的 `mean\|diff\| = 0.00 / 0.00 / 0.00` |
| 无论缩放 1.0 / 0.72 / 0.52 / 0.38，**四档都读作石材** | 见 `dev/_gen/grass_sim.png` 的对版 |

**根本原因**：ImageGen 给的是"有主体的画面"，而草地要的是"没有主体的纹理"。团簇在这个尺度就是**离散物体**，一定读成石头。

### 结论：程序化细叶贴图（v2.3 定稿配方 —— **以盘上这一版为准，不要重画**）

| 项 | 值 |
|---|---|
| 尺寸 / 通道 | **512 × 512，8bit 灰度（PNG colorType 0）**，均值对齐 **L\*≈50（≈RGB 117–118）** |
| 叶片 | **长 7–17px、宽 1–2px**（三段折线近似弯曲）、**方向 0–360° 全向** |
| **三层配比（v2.4 关键）** | 暗 0.28（10–16px / 74–106）· 中 0.38（8–14px / 106–144）· **受光 0.34（6–10px / 138–174）** —— 现版是 0.34 / 0.46 / **0.20（7–13px / 150–198）**，见 §B5.7 |
| 数量 | **5600 笔**；wrap 绘制：每片叶在 ±512 的 9 个偏移各画一次 → **天然无缝，不需要镜像** |
| 目标 std | **24 ± 2**（现版实测 24.00）。std 是"叶片与底色脱开程度"的代理量：>30 读作**刻痕**，<14 读作**塑料平板** |
| 超采样 | 画在 **2048** 上再 **4×4 box 平均**缩到 512（**不能用 LANCZOS**：卷积核会吃到画布外像素，接缝从 9 涨到 16） |
| 低频底座 | 2 组相位正弦叠出的低频亮度漂移，振幅仅 **±9**（只给"地形起伏"，不给物体）。**⚠️ 现 `dev/make_grass_texture.py` 没实现这一项 —— 规格与代码的缺口，见勘误 17。** 补上后 44px 尺度上才不会有"平滑绿板"感 |
| **绘制尺度** | **k3 = 0.75**（`overlay` α **0.40**）；**L4 = 0.47**（`soft-light` α **0.20**，0.47 = 0.75 × 0.62 → 比主层**更细**，只补高频微对比） |
| 文件 | ~150 KB（现版 152,480 B，md5 `18473a2e…`） |
| 命名 | `art/v9/tex_grass.png`（放 art/v9 会被 `dev/gen-asset-index.js` 自动扫进 `assets.js`） |

> **⚠️ v2.2 写的「26000 笔 / 叶长 3.5–7px / k3 = 1.5×」作废**，见勘误 13。那一组是给一个**从未产出过的贴图**配的参数，而盘上跑的是 5600 笔 / 7–17px。同一套约束下，5600 笔这张的正确答案是 **k3 = 0.75**，不是 1.5。

#### B5.1 三条约束（顺序不能换，密度永远是第一）

| # | 约束 | 形式 | 适用范围 |
|---|---|---|---|
| **C1** | **密度（硬，第一）** | 每格**草叶起点数** `N ∈ [40, 90]` | 硬约束：<40 读作"稀疏的塑料草茎"，>90 糊成噪点 |
| **C2** | **只许缩小（硬）** | `k ≤ 1.0` | 硬约束：k>1 是重采样放大，必虚（见 B5.4） |
| **C3** | **叶长（软，由 C1+C2 派生）** | 单叶屏显长度 中位 **5–11px（0.12–0.25 × cell）** | 软约束：只用来在 C1/C2 的可行域里挑点 |

#### B5.2 主公式（先算，再实测校）

```
C1:  N      = 笔数 / 512² × (cell / k)²           // 叶"起点"落进这一格的数量
C1'  笔数   = N × 512² × k² / cell²               // 反解：换贴图/换 k 时必须重算这个
C3:  L屏显  = 叶长(贴图 px) × k                    // 这是唯一跨贴图可比的不变量
```

代入现盘贴图（**5600 笔、叶长 7–17px（中位 12）、cell 44**）：

```
C1:  40 ≤ 5600/512² × (44/k)² ≤ 90
     → (44/k)² ∈ [1873, 4213]  →  44/k ∈ [43.3, 64.9]  →  k ∈ [0.68, 1.02]
C2:  k ≤ 1.0
C3:  5 ≤ 12k ≤ 11  →  k ∈ [0.42, 0.92]

三条取交集：  k ∈ [0.68, 0.92]      ← 定稿 0.75 落在窗口内偏「密」一侧（有意为之：宁可略密，不可偏稀）
```

> **两个口径并不互斥 —— 它们同时把 k 的上限压到 1.0 以下。**
> 主理人算的「要满足 k=2.2 得画到 27100 笔」是对的，但**那笔账只在"非要 k=2.2"时才需要付**；而 C3 本来就否决 2.2（叶长 15–37px）。所以重画贴图不是解，**把 k 降到 0.75 才是解，且零成本**。

#### B5.3 五次取值全部错在不同方向（这是本节最值钱的一张表）

| 阶段 | 贴图叶长 | 笔数 | k | **叶长屏显** | **N 起点** | 观感 | 违反了哪条 |
|---|---|---|---|---|---|---|---|
| v1 | 1–3px | 高 | **1.00** | 1–3px | 高 | 磨砂**砂纸** | **C3 下沿**（叶 < 5px） |
| v2 前半 | 1–3px | 高 | **0.55** | 0.6–1.7px | 更高 | 更细的砂纸 | **C3 下沿更严重**：把蕨团图的结论平移过来，方向反了 |
| v2.1 | 7–17px | 5600 | **2.20** | 15–37px | **8.5** | 散成单片大叶 | **C1（8.5<40）+ C3 上沿 + C2** |
| v2.2 | 7–17px | 5600 | **1.50** | 10.5–25.5px | **18.4** | 稀疏长白**刻痕** | **C1（18.4<40）+ C3 上沿 + C2** |
| **v2.3（定稿）** | **7–17px** | **5600** | **0.75** | **5.3–12.8px** | **73.5** | **草坪** ✅ | — |
| *（假想解）* | 3.5–7px | *26000* | 2.20 | 7.7–15.4px | **39.7**（刚够下限） | 也成立，但要重画贴图且**放大必虚**，不值得 | **C2**（得先破 C2 才行） |

一句话概括这条弯路：
> **k 单独没有意义。有意义的只有「叶长屏显」和「每格起点数」这两个屏显量；k 是它们的分母/乘数。**
> 谁只调 k 而不先说"我这张贴图的叶长是多少"，就一定会来回过冲 —— 我冲了四次。

#### B5.4 为什么 k 只许 ≤1，不许放大（"刻痕感"的物理来源）

| k | 一个纹理 px 占几个**设备** px（dpr 2） | 重采样 | 叶片边缘 |
|---|---|---|---|
| **0.75** | **1.5** | **4/3 降采样**（天然抗锯齿） | 边缘更**干净**，反而变锐 |
| 1.00 | 2 | 1:1（无重采样） | 保持原始像素台阶 |
| 1.50 | 3 | 1.5× 双线性放大 | 每个叶缘糊成 3px 渐变 → 叶片**变胖变软** |
| 2.20 | 4.4 | 2.2× 双线性放大 | 叶缘 4–5px 渐变 → 读作**羽毛/划痕** |

> **放大发虚不能靠"把源图做大"解决**：512 → 1536 体积 ×9，而且只是把同一个虚按比例放大。
> **缩小**这条路不用付任何代价：同一张 512² 图铺得更小 → 每个叶子摊到的设备像素更少 → 视觉上更细密，正好是草地要的方向。
> **结论：k 的默认值是 0.75，不是 1.0。** 只有在贴图叶长 <4px（细到看不见）时才允许往上调，且不得超过 1.0。

#### B5.5 换贴图/改 k 必须重算（给下一个人）

改任何一项，都要按顺序过这四步，缺一步就会重演上面的弯路：

1. 量出**新贴图的叶长中位数**（不是最长也不是范围中点，是中位）→ 算 `L屏显 = 叶长 × k`，必须落在 **5–11px**。
2. 算 `N = 笔数/512² × (cell/k)²`，必须落在 **[40, 90]**。超了 → `笔数 = N × 512² × k² / cell²` 反解出该画多少笔。
3. 确认 `k ≤ 1.0`。若反解出的 k > 1，**说明贴图叶长太长，回去把叶子画短，不要放大**。
4. 跑 `dev/grass-acceptance.js`（B8）+ 出 6 档 k 对版图（`dev/_gen/_art_k_decision.py` 可直接复用）人眼复核。

> **实测口径补充**：`grass-acceptance.js` 跑出来的"可辨叶数"会比 `N` 大 1.5–2.5×，因为**叶子的起点在格外时，叶身仍有一截伸进格内**（k 越大、叶越长，伸进来的比例越高）。所以：
> - **判断"该画多少笔"用 `N`（算式，可复现）**；
> - **判断"看着稀不稀"用像素实测或人眼**；
> - 两者不要混着比，很容易得出"k=1.5 也有 51 根，密度合格"的错觉 —— 而 1.5 其实是**被叶长（10.5–25.5px）和放大发虚否决的**，不是被密度否决的。

#### B5.6 六档 k 对版图（定案证据）

`dev/_gen/_art_k_decision.png` —— 用**盘上这张**贴图，按 L3 的 `overlay` 合成 2×2 格，6× 硬放大：

| k | 观感（我的判定） |
|---|---|
| 0.55 | 细到发干，**砂纸/苔藓** |
| **0.75** | **细密、单叶可辨、密而不糊 —— 定稿** |
| 1.00 | 仍然成立，单叶更清楚，已到**可接受上限** |
| 1.25 | 偏疏，开始看到"一根一根" |
| 1.50 | **稀疏 + 长白刻痕**，叶与底色脱开 |
| 2.20 | 明显的**划痕/羽毛**，草感消失 |

> 这张图同时否掉了 v1(1.0 偏砂)、v2 前半(0.55 更砂)、v2.1(2.2 划痕)、v2.2(1.5 刻痕) 四个值 —— **它们是同一个错误在四个不同刻度上的投影。**

#### B5.7 **感知密度 ≠ 总笔数**：眼睛只数「受光层」（v2.4 新增，这条推翻了 C1 的单一口径）

我在 k=0.75 的实拍棋盘（`dev/_gen/board_after.png`）上做了 3× 放大复核，看到的**不是草坪**，是：

> 一块平滑的绿色板，上面撒着浅色的短碎条 —— 像撒了亮片/纤维丝，不像草。

数一下：**每格只能数出约 15 根**明显的浅色短条，但 `N`（总起点数）是 74。差了 5 倍。原因很清楚：

| 层 | 占比 | 笔数 | 每格可见 | 明度（底 118） | 观感 |
|---|---|---|---|---|---|
| 暗叶 | 0.34 | 1904 | ~25 | 72–106（−46…−12） | 读作"底色里的暗纹"，**不像叶** |
| 中性叶 | 0.46 | 2576 | ~34 | 108–146（−10…+28） | 与底色差太小，**糊进底色** |
| **受光叶** | **0.20** | **1120** | **~15** | **150–198（+32…+80）** | **唯一被眼睛当成"叶"的层**，但它们太亮太长 → 读作浅色碎条 |

**结论：`N` 是"画了多少笔"，不是"眼睛看到几根叶"。眼睛只数得清对比度足够的那一层。**
所以 C1 需要补一个下位判据：

> **C1b（感知密度）：受光层的每格可见根数 ∈ [25, 45]，且受光层与底色的明度差 ≤ +56。**
> 现版受光层 15 根 / 差 +80 → 太少又太亮 = **撒亮片**。
> 反例：把受光层加到 26000 笔（v2.2 的做法）只会让"亮片"变"亮粉"，更糟。

**为什么不加总笔数**：C1 已经算出 k=0.75 时 `N` 上限对应的笔数是 **6850**，现版 5600 只剩 22% 余量。加到 26000 会直接顶破 `N ≤ 90`（变成 341 根/格）。**密度预算已经快花完，只能重新分配三层，不能加水。** 这就是 v2.4 把配比改成 `0.28 / 0.38 / 0.34`、并把受光层压到 `138–174` 的原因。

> 这条也是对我自己的一个纠正：我一直在用 `N`（一个**作者侧**的量）当验收判据，而 B8-7 要的是**观者侧**的量。以后报"每格多少根"必须写清楚是**总笔数法**还是**受光层法**。

#### 无缝判据（修正 v1/v2 的错误口径）

我 v1 写"接缝差 0.00 = 无缝"，**这是错的**：0.00 恰恰是**镜像拼接的指纹**（左右两列被强制成同一列）。随机细叶纹理的相邻列本来就差 14 左右，接缝只要**不显著大于相邻列基线**就是无缝。

| 指标 | 现版实测 | 判据 |
|---|---|---|
| 接缝列差 | **1.94** | ≤ 相邻列基线（**14.05**）✅ |
| 接缝行差 | **0.58** | ≤ 相邻行基线（**7.34**）✅ |
| 水平/垂直/180° 镜像差 | **21.45 / 21.23 / 21.46** | 必须 **> 15**（证明没有对称指纹）✅ |

**以后一律用这三行判无缝，不要再看"0.00"。**

**L4 为什么取 0.47（= k3 × 0.62）**：L4 的职责是**补高频微对比**（厚薄不均/叶片疏密），所以必须**比主层更细**，0.47 < 0.75 就是这个关系。反过来说，把 L4 也放到比主层更粗（例如 k3=0.75 时取 L4=1.6）会怎样：实测整盘平均亮度从 111.9 掉到 104.7（≈ −6 L\*），并出现大块暗斑（读作泥斑/阴影）→ **直接违反 B8-3 的「整盘均值偏差 ≤3」**。想保留大尺度层次只能把 α4 降到 0.14 并放宽 B8-3，不划算。
> **勘误 14**：v2.2 我写的是"L4 应比主层**更低频**（2.45 vs 1.5）"，那是在 k3 被错误抬到 1.5 的前提下的自洽结论；k3 回到 0.75 后，主层本身已足够细，L4 必须回到**更细**一侧（0.47），否则就是上面那 −6 L\* 的泥斑。

**为什么灰度**：`overlay` / `soft-light` 只用**亮度**。灰度贴图 = 只喂亮度结构，色相全由 L0 与 L7 决定 → 格子双色、暖冷、阵营色一个都不会跑偏。绿色贴图会绿叠绿爆饱和并抹平双色。

**作者侧可检查的量化口径**（比任何图像指标都准）：
> **一个 42–44px 格内必须能数出 40–90 根可辨细叶**（定稿配置 cell 44 / k 0.75 下 `N` = 73.5）。
> 少于 20 根 → 你在画石头；多于 120 根 → 会糊成噪点。
> 这条**必须和"单片叶屏显长度 5–11px"一起满足**：只看根数会做出"很多长叶"=刻痕的效果（这就是 k=1.5 的失败方式：根数其实还够，但叶长到了 25px）。
> （ImageGen 蕨团图每格只有 6–10 个团块，这就是它失败的量化证据。）

### 叠加顺序（不能调）

```
L0 底色 → L1 光楔 → L2 簇斑 → L3 贴图(overlay .40) → L4 贴图(soft-light .20)
        → L5 草尖(lighter) → L6 微点 → L7 阵营色调(soft-light) → L8 雕刻格线
```
- L3/L4 必须在 L2 之后：簇斑是大结构、贴图是表面细节。
- L8 永远最后：可读性的保险。

### 加载时序（实现方已踩过，保留为必做项）

```
buildBackground 内：
  var tex = ART.img('tex_grass.png');
  if (!tex) { 跳过 L3/L4，并记 bgTexPending = true; }   // 不要把 bgKey 当已构建完成
构建完成后：若 bgTexPending → 渲染循环每帧查一次；一旦可用 → bgKey = ''; buildBackground();  // 只重建一次
```
**不要为等贴图延迟首帧。** 新资产落地后**必须重跑 `dev/gen-asset-index.js`**，否则 `ART.img()` 永远拿不到。

> **✅ 已验证**（实现方按此落地）：`bgTexPending` 标记 + 就绪后 `bgKey=''` 重建一次，实测 `builds=2` —— 即"首帧无贴图 → 贴图到达后重建一次"，没有反复重建。此条视为已闭环。

> **第 7 条为什么必须有**：v1 方案在 1–6 条里过了 5 条（含"L\* 极差 30.1"这种看起来很好的数），**但肉眼读作鹅卵石**。我还试过用"低频明暗极差"当客观代理指标，实测细叶图 9.0 / 蕨团图 8.9 —— **完全分不开**。这不是亮度频率问题，是"有物体感"的形态问题。所以：**数值是必要条件，不是充分条件；每次换贴图必须有一张 100% 截图人工过一票。**

> **贴图尺度是第 7 条的子项**：同一张贴图，k=0.55 读作砂纸、**0.75 是唯一可用档**、1.5 读作长白刻痕、2.2 读作划痕（见 B5.6 六档表）。**但"k 对了"只解决了尺度那一半** —— 0.75 下贴图仍因受光层太亮太少而读作"绿板撒亮片"（B5.7）。**尺度（k）与内容（三层配比）是两个独立的闸门，都要过。**
